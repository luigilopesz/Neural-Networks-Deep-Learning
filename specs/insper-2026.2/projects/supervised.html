Project: Classification or Regression with neural networks

Second delivery of the project. The team trains a neural network on the same dataset as the EDA, on the task chosen in the proposal: classification or regression, only one. The EDA's pipeline is the starting point. The question of this delivery: does the network learn something simpler models do not? And how far can the number it reports be trusted?

Rules

  • Network required: an MLP (or deeper) in PyTorch, Keras/TensorFlow or NumPy written by the team. scikit-learn's MLPClassifier/MLPRegressor only counts as a baseline.
  • Same dataset, same task and same train/test split as the EDA, with the same seed. The validation set comes out of the training set.
  • The test set is used once, in step 5, after everything was decided on validation. If it helped choose anything, say so in the report: step 5 is then worth up to half.
  • Fixed seeds, figures numbered with a title, axes and a legend; every number asked for appears in the text.

Steps

  • 0 · Starting point · 0.5

    • The EDA pipeline imported from code/, fitted on the training set only, with the fixes the EDA's grading pointed out.
    • The main metric and the success criterion written down before training: "MAE at least 15% lower than the best baseline's".

  • 1 · Baselines · 1.0

    • A trivial one (majority class or training mean, Dummy*) and a linear one (logistic or linear/Ridge), on the same pipeline, evaluated on validation.
    • Optional: random forest or boosting. On tables they often tie with the network; if so, say it.

  • 2 · The network · 2.0

    • Layers, widths, activations and initialization justified; number of parameters compared with the number of training rows.
    • Output and loss consistent with the task (below). Network and loop in files under code/.

  • 3 · Training · 1.5

    • Optimizer (SGD with momentum, Adam or AdamW), learning rate, batch and epochs, with the reason.
    • Early stopping on validation, restoring the best weights.
    • Curves of training and validation per epoch, read: does it converge? where does overfitting start?

  • 4 · Regularization and hyperparameters · 2.0

    • Two or more techniques (weight decay, dropout, BatchNorm/LayerNorm…) compared with the network without any.
    • A search of 8 or more configurations (learning rate, width/depth, regularization) chosen on validation, in a sorted table.

  • 5 · Test evaluation · 1.5

    • The chosen configuration, retrained and evaluated once, with the task's metrics (below).
    • One table with the network and the baselines on the same test set: was the criterion of step 0 met?
    • 3 or more seeds (mean ± std): is the gap to the baseline larger than that variation?

  • 6 · Error analysis · 1.0

    • The error per subgroup (a category from the EDA, ranges of the target) and the worst examples, with a hypothesis for each pattern.
    • Permutation importance: does it match what the EDA suggested?

  • 7 · Conclusion · 0.5

    • Was the network worth it? Limitations, who would be affected by an error and what you would do with more time.
    • The results summary table filled in.

Test metrics confusion matrix, precision, recall and F1 per class, macro F1, ROC-AUC; if imbalanced, the precision-recall curve and PR-AUC
Threshold chosen on validation, justified by the cost of the errors

Skeleton of the training loop with early stopping (PyTorch) 
best, wait = float("inf"), 0
for epoch in range(max_epochs):
    model.train()
    for xb, yb in train_loader:
        optimizer.zero_grad()
        loss = loss_fn(model(xb), yb)
        loss.backward()
        optimizer.step()

    model.eval()
    with torch.no_grad():
        val_loss = loss_fn(model(X_val), y_val).item()
    if val_loss < best:
        best, wait = val_loss, 0
        torch.save(model.state_dict(), "best.pt")   # keep the best weights
    else:
        wait += 1
        if wait == patience:
            break
model.load_state_dict(torch.load("best.pt"))
